# UR Tutor

An adaptive AI tutoring system where you learn a topic **one concept at a time** and a topic is only marked **complete after you pass its quiz**. It is built on a [`deepagents`](https://pypi.org/project/deepagents/) harness running **Anthropic Claude Haiku 4.5**, with per-user accounts, isolated multi-session chat, skills-driven teaching, and a mastery-gated progress engine.

**Checkout the website:** https://urtutor.netlify.app/

**Version:** `3.0.0`

---

## How it works

1. **You pick a topic.** The tutor first asks your level (**Beginner / Intermediate / Advanced**) — a hard gate; nothing is taught until you choose.
2. **It builds a curriculum** of 4–8 concepts and teaches **one concept per turn**, ending each turn with a short comprehension check.
3. **Mastery is earned, not assumed.** A concept is marked *mastered* only after you pass its check. Progress % = concepts mastered ÷ total.
4. **The quiz is the gate.** When you ask for / are ready for the quiz, the tutor generates multiple-choice questions. The topic flips to **complete only when you score ≥ the pass threshold (default 80%) AND every concept is mastered** — enforced in code, not by the model.

The difficulty prompt and the quiz render as **interactive choice cards** above the chat box (click to answer; quizzes are paginated).

### Bring your own key

UR Tutor calls Claude with **your own Anthropic API key** — the server holds no model credentials.

- Add the key from the 🔑 button in the header (the dot is green once a key is stored). It is checked against Anthropic — via `POST /key/validate`, which costs no tokens — before it is saved.
- The key is kept **in your browser** and sent with each message in the `X-Anthropic-Key` header. It is never written to the server or the database.
- Storage is **`sessionStorage` by default**, so the key is forgotten when you close the tab. Tick *Remember on this device* to use `localStorage` instead.
- Sending a message without a key opens the key panel instead: the backend independently rejects keyless `/chat` calls with `428 Precondition Required`.
- Logging out clears the stored key from both stores.

**Keeping the key safe.** A key held in the browser is exposed to any script that runs on the origin, so the frontend is locked down accordingly:

- A strict **Content-Security-Policy** ships with the build (`dist/_headers`, generated by `vite.config.ts`). `script-src 'self'` allows no inline or third-party script, and `connect-src` is limited to the app's own origin plus the API — so injected code has no channel to send a key anywhere. `connect-src` is generated from `VITE_API_BASE_URL` at build time, so it cannot drift from the backend the bundle was built against.
- The app loads **no third-party scripts** and needs no `unsafe-eval`.
- The backend **never logs the key** and never echoes raw exception text to the browser — model errors are mapped to fixed, safe messages (`_friendly_error` in `api/routes.py`), with full detail kept in the server log.
- Use a **dedicated key with a spend limit** rather than your main one, and revoke it when you're done. The key panel says so too.

### Architecture

```
React (Vite) ──HTTPS/JWT──> FastAPI
                              ├─ Auth (OAuth2 password + JWT)
                              ├─ Deep agent harness (deepagents + Claude Haiku 4.5)
                              │    ├─ skills: teach / quiz / evaluate  (SKILL.md files)
                              │    ├─ progress tools  (curriculum, mastery, quiz gate)
                              │    └─ CompositeBackend: StateBackend (per-session scratch)
                              │                         + StoreBackend /memories (per-user)
                              ├─ Checkpointer: AsyncSqliteSaver  (conversation state)
                              └─ Authoritative records: SQLite (users, topics, concepts, quizzes, sessions)
```

**Isolation:** identity comes from the verified JWT (never the client). Conversation state is keyed by `thread_id = "<user_id>:<session_id>"`; durable agent memory is namespaced to the authenticated user. One user's data can never surface in another's session.

## API

**Base URL (local):** `http://localhost:8000` · **Swagger:** `http://localhost:8000/docs`
**Auth:** OAuth2 password flow → JWT bearer token (use Swagger's **Authorize** button).

| Method | Path | Auth | Purpose |
|---|---|---|---|
| `POST` | `/auth/register` | — | Create an account → returns a token |
| `POST` | `/auth/token` | — | Log in (form `username`/`password`) → token |
| `GET`  | `/auth/me` | ✅ | Current user |
| `POST` | `/chat` | ✅ | Streamed tutoring turn (`{message, session_id}`) |
| `GET`  | `/sessions` | ✅ | List the user's chat sessions |
| `POST` | `/sessions` | ✅ | Create a new chat session |
| `GET`  | `/sessions/{id}/messages` | ✅ | Transcript for a session |
| `DELETE` | `/sessions/{id}` | ✅ | Delete a session + its conversation |
| `GET`  | `/progress` | ✅ | All topics with status + percent |
| `GET`  | `/progress/{topic}` | ✅ | One topic's progress |
| `POST` | `/session/reset` | ✅ | Clear one session's chat memory (progress kept) |
| `GET`  | `/health` | — | Health check |

`/chat` returns a `text/plain` token stream. The tutor may append an interactive block — `[[CHOICES]]{...}[[/CHOICES]]` — which the frontend renders as a choice/quiz card and strips from the visible text.

## Local development

**Prerequisites:** Python 3.12, Node.js 18+, and your own [Anthropic API key](https://console.anthropic.com/settings/keys) with access to `claude-haiku-4-5`. The key is entered in the app, not in `.env`.

### Backend

```bash
cd backend
pip install -r requirements.txt
cp .env.example .env
python -m uvicorn main:app --reload --port 8000
```


### Frontend

```bash
cd frontend
npm install
cp .env.example .env
npm run dev         
```

`npm run build` emits `dist/_headers` alongside the bundle; Netlify picks it up automatically when `dist` is the publish directory. Set `VITE_API_BASE_URL` in the Netlify environment so the CSP's `connect-src` names the deployed backend. (The CSP applies to the built site only — `npm run dev` is unaffected.)

## Notes

- Registration is currently open. Chat spend lands on each user's own Anthropic key, but consider rate limiting / an invite gate before exposing the app publicly.
- The API key is only as private as the user's browser. The CSP and session-scoped storage shrink that exposure, but they do not eliminate it — if you ever add a third-party script or a CDN dependency to the frontend, revisit the policy in `vite.config.ts` first.
